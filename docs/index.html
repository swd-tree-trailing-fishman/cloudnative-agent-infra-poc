🎯 5つのコア機能

🔀 A. Feature ToggleGo

X-Region ヘッダーでJP/TW/KRを判定し、応答言語・推薦エンジン・フラグを動的に切り替え。 ConfigMapで環境全体のフラグを制御。

学習ポイント: 環境変数によるフィーチャーフラグ、リクエスト単位の設定注入

🔭 B. Agent ObservabilityOTLP

APIリクエスト〜LLM呼び出し〜レスポンスまでの全経路をOpenTelemetryで計装。 OTLP Collector → Jaeger でウォーターフォール表示。

学習ポイント: 分散トレース、スパン伝播、OTLP gRPCエクスポート

📦 C. Agent SandboxK8s

コード実行リクエストを受け取ると、Kubernetes APIで一時的なJob Podを動的生成。 TTL 60秒で自動削除。readOnly + nonRoot で安全に隔離。

学習ポイント: K8s Dynamic Resource Creation, RBAC 最小権限

⚡ D. Event-driven MigrationKEDADjango

LocalStack SQS にメッセージを投入するとKEDAが検知し、ScaledJobを自動起動。 Django APIからboto3でイベント送信。最大5並列でマイグレーション実行。

学習ポイント: イベント駆動アーキテクチャ、KEDA ScaledJob、boto3

🕸 E. Ambient NetworkingIstio

サイドカーなしでmTLSを実現するIstio Ambient Mode。 ztunnel (Node L4) + Waypoint Proxy (Service L7) の二層構造。 Sandbox NamespaceからのInboundを AuthorizationPolicy で拒否。

学習ポイント: サービスメッシュ、ゼロトラスト、mTLS STRICT

WSLターミナルでコピペ実行するだけで全環境が立ち上がります。

# Go + Django をビルド → Kind にロード → K8s にデプロイ

③ ポートフォワード（別ターミナルで）

# Go API → localhost:8080

# Jaeger UI → localhost:16686

④ 動作確認

# Feature Toggle: JP/TW/KR でリージョン切り替え

# Agent Sandbox: K8s Job 動的生成テスト

# Event-driven Migration: SQS → KEDA → Job E2E
make test-migration

🧠 学習ポイント まとめ

🐹 Go — Cloud Native パターン

  • signal.NotifyContext による Graceful Shutdown
  • rest.InClusterConfig() → K8s 動的リソース生成
  • otel.Tracer() で子スパン作成・属性付与
  • 環境変数によるフィーチャーフラグ制御
  • distroless イメージで攻撃面を最小化

🐍 Python / Django — SRE 実装

  • with tracer.start_as_current_span() でスパン自動終了
  • boto3.client("sqs") でLocalStack SQS連携
  • @csrf_exempt + @require_http_methods デコレーター
  • JsonResponse でRESTful APIレスポンス
  • gunicorn + WSGI 本番デプロイパターン

☸ Kubernetes — 運用パターン

  • RBAC 最小権限 (Role + RoleBinding)
  • TTLSecondsAfterFinished で Job 自動クリーンアップ
  • readOnlyRootFilesystem + runAsNonRoot セキュリティ
  • ConfigMap による設定外部化
  • KEDA ScaledJob でイベント駆動オートスケール

🕸 Istio Ambient — ゼロトラスト

  • Namespace ラベルのみでmTLS有効化 (サイドカー不要)
  • ztunnel (L4) + Waypoint (L7) の二層分離
  • PeerAuthentication STRICT で全通信暗号化
  • AuthorizationPolicy で Namespace 間アクセス制御
  • VirtualService でヘッダーベースルーティング
